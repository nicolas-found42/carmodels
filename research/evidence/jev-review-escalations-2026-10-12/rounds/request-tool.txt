Task from the user: when a Jev review escalates, research the reasons and fix the code until Jev reaches 0.95 across the board.
Research result (controlled jev_review experiments with retained receipts): tools/review_payload.py split a change into 24,000-character whole-diff slices, so each slice was judged against the whole request and scored as a partial match; it sent the check manifest JSON as test output instead of logs of the tests exercising the change; logs did not name tests; nothing told the judge which modules consume a changed file; and the verifier had to count manifest rows itself. jev-mcp 0.13.0 has a per-file mode (files: [{path, diff}], up to 16 files, 200,000 characters, 50,000 per file) where each file is judged with the whole change visible.
Change: build makes one per-file jev_review call when the scope fits (grouped calls otherwise or with --grouped); tests carries computed scope facts (added/modified/deleted, same-directory importers), a computed check summary and the full logs of checks naming an in-scope file (50,000-character budget, never truncated); verify evidence starts with the computed summary and carries the full logs of the checks its claims name (every log when none is named); any call above 90,000 characters is refused before sending, because larger calls failed upstream with max_tokens_exceeded; status validates every per-file result (each file accounted for with valid scores; an auto aggregate cannot hide an unresolved file). New tools/line_coverage.py reports stdlib-trace line coverage with a --minimum gate. docs/agents/review-workflow.md documents the mode. Existing fail-closed rules are unchanged.
