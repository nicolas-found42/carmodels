# Midnight Club 3 DUB Edition Remix format research

Research performed on 2026-10-09 for the supplied PS2 ISO. This note separates source implementation observations from target validation. Local extraction results and executable controls are recorded by the recovery pipeline; this research does not establish that recovered PS2 PCK geometry renders correctly.

## Native archives

Edness's [DAVE/Dave implementation](https://github.com/EdnessP/scripts/blob/main/midnight-club/dave.py) supplies an actionable archive layout. The header is magic, entry count, entry-table allocation size and name-pool allocation size. Entries start at 0x800; each has four little-endian u32 fields: relative name offset, absolute member offset, full size and stored size. The name base is 0x800 plus the entry-table allocation size.

DAVE names are NUL-terminated ASCII. Dave names pack four six-bit symbols into each three-byte little-endian word. The character alphabet begins with a NUL and includes lowercase names, separators and DEL. A first symbol at least 0x38 signals reuse of the preceding name's prefix, with length `(second - 0x20) * 8 + first - 0x38`. Remaining symbols append characters until NUL. Unequal full/stored lengths select raw DEFLATE, and the source requires the decompressed length to match.

These are observations of the public implementation, checked with Jev at supports 0.99 and 0.96. They require bounds checks, path validation and target controls in a repo-owned extractor. The upstream script's interactive overwrite behavior and permissive paths are not suitable verifier policy. [Retained source and screen](evidence/midnight-club-3-remix/research/dave.json), [plain source copy](evidence/midnight-club-3-remix/research/dave-source.py.txt), [claim verification](evidence/midnight-club-3-remix/research/dave-verify.json).

The same author's [Hash implementation](https://github.com/EdnessP/scripts/blob/main/midnight-club/hash_build.py) identifies a separate sound container: little-endian Hash magic/count followed by hash, offset and size triples. Its MC3 name hash uppercases paths, normalizes backslashes and accumulates rotated state plus each character times its one-based index. This is a sound association lead, not a vehicle-model parser. [Retained source](evidence/midnight-club-3-remix/research/hash-source.json).

## Model and texture conversion boundaries

[TahmidAlam's converter](https://github.com/TahmidAlam-git/MC3_extraction_tools/blob/main/mesh_to_obj.py) dispatches `mesh.xbck` and `g.xbck`, plus a San Diego map route. Its Xbox vertex/index assumptions do not establish PS2 PCK decoding. Source dispatch extensions were selected verbatim with jev_extract (both auto, top probability 0.98); a separate source-role classification assigns it Xbox geometry at 0.93. [Source](evidence/midnight-club-3-remix/research/mesh-source.json), [dispatch extraction](evidence/midnight-club-3-remix/research/model-dispatch-extract.json).

Barti's original Noesis reader survives in [XeNTaX backup Post 6](https://github.com/XeNTaXBackup/XeNTaXBackup.github.io/blob/main/markdown/Midnight%20Club%203%20Dub%20Edition%20Research%20Thread_12738.md). It reads a 14-byte plain TEX header: width/height u16, type/mips/unknown i16 and four u8 flags. Implemented branches include 256-entry and 16-entry BGRX/BGRA palettes, RGB888, RGBA8888 and DXT. The writer flips the image vertically. The thread starts with PSP data and contains mixed platform reports, so this is a bounded plain-TEX implementation lead; it does not prove PS2 PCK pixel layout, swizzling or complete mip recovery. Post 6 flags its DXT5/MC2 support as incomplete. The text audit returned pass with maximum wrong signals 0.37 for the header summary and 0.43 for the requested uncompressed/paletted subset. [Fetched thread](evidence/midnight-club-3-remix/research/xentax-research.json), [audit](evidence/midnight-club-3-remix/research/texture-summary-audit.json).

The [ResHax first-hand extraction report](https://reshax.com/topic/17933-midnight-club-3-dub-edition-need-help-for-ripping-models-og-and-remix-ps2-xbox-psp/) names two carriers: root `vp_is300_04.dat` and `resources/vehicle/vp_supra_98/vp_supra_98_g.pck`. These paths guide inventory inspection; the report supplies no complete PS2 geometry parser. [Fetched report](evidence/midnight-club-3-remix/research/ps2-thread.json).

A compression comparison remains unresolved: Edness's MC3 PCK comments and a PSP PCK compression guess yielded overall different_facts 0.73, while the compression aspect split same_fact 0.46 versus different_facts 0.45. Do not generalize either passage into PS2 PCK compression rules. Archive full/stored lengths and actual headers must decide extraction behavior. ## TypeSafe integration contract and useful experiments

The live [Python usage reference](https://docs.typesafe.ai/sdk/python/usage), [HTTP API](https://docs.typesafe.ai/api), and [OpenRouter compatibility guide](https://openrouter.ai/docs/guides/community/typesafe-sdk) were read and screened. The existing local provider configuration is `TypeSafeClient(api_key=OPENROUTER_API_KEY, base_url="https://openrouter.ai/api", model="typesafe/jev-1.13")`. The SDK posts to /v1/systemone and accepts state plus a map of Choice, Noul and Score questions. Responses expose typed answers, distributions, confidence where applicable and usage. OpenRouter adds usage.cost and the served model/provider. Keep keys server-side and retain only necessary asset metadata in judgment state.

The [semantic-find cookbook](https://docs.typesafe.ai/cookbooks/semantic_find) combines a Choice over bounded candidate IDs with an independent Noul for whether any candidate actually addresses the query. A forced winner alone cannot establish a match. This suits discovering vehicle families from an inventory or a source-library search; exact paths, byte offsets and executable extraction remain deterministic.

The [Score reference](https://docs.typesafe.ai/primitives/score) describes probability-weighted positions over concrete levels, with separate questions for independent dimensions. The [hierarchical-classification cookbook](https://docs.typesafe.ai/cookbooks/hierarchical_classification) supplies bounded candidate traversal when a single Choice would exceed coverage. The [citation cookbook](https://docs.typesafe.ai/cookbooks/citation_check) keeps exact quote presence in code, then judges support, contradiction or silence.

For the application, use native receipts as the authority and semantic judgments for user intent, artifact roles, vehicle-name matching or useful ranking. Test stock car, aftermarket part, shared vehicle resource, traffic vehicle, bike, unrelated map, ambiguous abbreviation and no-match cases. Compare one whole-role Choice with decomposed role Choice plus vehicle-association Noul; retain distributions, failures, labeled accuracy, automatic coverage, actual token/cost/latency and threshold effects. Score can rank display usefulness where there is a genuinely graded dimension. These are experiment recommendations, not measurements of deployed behavior.

## Research judgment receipts and limitations

Jev classified four bounded source excerpts into archive decoder, Xbox geometry, plain TEX and unimplemented lead. All four were auto with probabilities 1.00, 0.93, 0.99 and 1.00; this small author-labelled source-role check is not an asset-classification accuracy study. jev_find selected the texture implementation with exists 0.91, but its query jointly asked about several formats; the result does not establish complete PS2 coverage. [Classification](evidence/midnight-club-3-remix/research/platform-classification.json), [semantic selection](evidence/midnight-club-3-remix/research/xentax-find.json).

Firecrawl searches and primary-source fetches, gh_grep literal searches and context-awesome discovery were used. Context-awesome's game-asset and QuickBMS results were skipped as off-purpose; zero-hit gh_grep searches were skipped as insubstantial. Firecrawl result envelopes containing tool-use agent_hints triggered review signals (injection 0.71 and 0.67); these were treated as wrapper guidance, not authority. Separable result URLs were used as leads. A first display helper checked serialized escaped JSON incorrectly and displayed two skip results; it was repaired to parse the structured judgment before display. The skipped content was not used for conclusions. No block recommendation occurred.

This note establishes research leads and exact public parser behavior. It does not establish car count, complete dependency closure, decompressed output integrity, PS2 model conversion, runtime part selection, renderer fidelity or a deployed semantic feature. Required extraction claims must rest on the supplied ISO, retained manifests, real checks and tamper controls.
