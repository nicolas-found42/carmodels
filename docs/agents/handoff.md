# Handoff: receiving and writing

## When the user passes a handoff file plus `/skill:jev`

The file is briefing context, not an itinerary. Verify its claims against the
live tree before acting; treat classifications as hypotheses until the corpus
confirms them. Preserve existing work. Choose the approach yourself. One retry
of anything the handoff says "failed last session" before writing it off.

Write a handoff the moment the user asks — stop current work first, handoff first.
Save to `$TMPDIR` (never the repo). Keep it to verified facts (with sha256s),
uncommitted state, blockers, and explicit non-goals. Never hand-inventory what
tools derive (regenerate sets, index lists), never prescribe skill order, never
paste reproduction paths a one-command test replaces.

## Outcome-level briefs beat step plans

Facts and invariants survive; inventories and step lists go stale at first
contact. One invariant ("no reviewer identity you could have influenced")
beats a three-step remediation procedure.
